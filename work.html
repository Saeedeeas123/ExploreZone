Modules I've built.

Standalone Android tools, each written as a module rather than an app feature — so any future app can pick one up without re-debugging it.

  • AI-LLMv0.2.0
    core-llm
    An OpenAI-compatible LLM client for Android with an API-key vault backed by the Android Keystore. Zero third-party dependencies — it talks to any provider, or to a local llama.cpp, Ollama or LM Studio server.
    Repository →
  • AI-LLMv0.1.0
    core-litertlm
    A safe, app-agnostic loader for Google's LiteRT-LM (.litertlm) models. It validates the file's magic header before the native layer ever sees it, refuses to run on the main thread, and turns every failure into a message that says what to do.
    Repository →
  • AI-LLMv0.1.0
    core-llamacpp
    Runs GGUF models fully on-device through llama.cpp — CPU only, arm64-v8a, with the ARM dot-product kernels actually enabled in the shipped build.
    Repository →
  • Input-UIv0.1.1
    minikeys-keyboard
    A modular Android keyboard (IME): the input method, the settings model and a canvas-drawn keyboard view, split into reusable modules instead of one app.
    Repository →
  • Input-UIv0.2.0
    stickkeys-edge-keys
    Vertical key strips pinned to both screen edges. Tap a key and the sticker, emoji or GIF you picked lands on the clipboard — overlay permission only, no keyboard involved.
    Repository →
  • Input-UIv0.1.0
    minikeys-shortcut
    Always-on edge keys that act on the app in front of you: type into its focused field, send a real key combination, or press that screen's own buttons through the accessibility service.
    Repository →
