Engineering finding · 2026-10 · on-device inference · root cause

Zero tokens from a perfectly good GGUF model

Verified on deviceLLMllama.cppJNI

Symptom

An on-device GGUF model loaded successfully, reported its metadata correctly, accepted a prompt, and then generated nothing. Every call returned an empty result. No exception, no error code, no crash — just silence.

Root cause

The chat template was being applied with the “add assistant” flag set to false. The practical effect: the formatted prompt ended at the user's <end_of_turn> marker. Greedy decoding then did exactly what it was asked to do — it continued the text with the most likely next token, which was another <end_of_turn> (token 106, an end-of-generation token). Generation stopped immediately, correctly, with zero content tokens.

With the flag set to true, the prompt ends with <start_of_turn>model, and the model answers normally.

Evidence

  • Same model file, same code path, one boolean changed: empty output → the model replies “OK”.
  • Confirmed on the physical device by a human, not only in a probe.
  • The failing token was identifiable as a specific end-of-generation token, which is what turned a mysterious “no output” into a one-line explanation.

Second defect, same session: the cache is not reset

With generation working, a new failure appeared: after roughly seven turns on a 512-token context, the session died — succeeding calls gave way to empty results, and prefill then started returning an error. The model was not broken; the conversation state was never cleared between calls.

Clearing the memory per call turned 7 successful calls into 20 out of 20.

What I would tell the next person If a local model generates zero tokens while reporting success, check the prompt formatting before you touch the model, the quantization, or the build. Greedy decoding is not silent by accident — it is usually obeying a prompt you did not intend to send. And if a local model works then stops working after N turns, suspect retained state before suspecting the weights.

Honest limits

These findings came out of a feature that was later removed from the product for unrelated reasons — a different engine crashed without leaving any evidence to investigate. The engine these two bugs belong to was working and verified by the time it was removed, so the findings stand on their own; but nothing here should be read as “the whole offline stack was production-ready”.
